# 07: Safely apply the complete workflow to an existing Collection

**What to build:** An author can run the integrated YAML, Note Type, Template, styling, tag, and new-managed-Card placement workflow against an existing Collection through a guarded command. It first backs up and rehearses on a consistent disposable copy, then permits explicitly approved live updates only with Anki Desktop closed. Existing Card Deck placement is preserved without mismatch reporting.

**Blocked by:** 05 — Apply Note Types, Templates, and shared styling; 06 — Verify new managed Card placement in linked Decks.

**Status:** ready-for-agent

- [ ] Validate the explicitly selected profile/Collection, compatible Anki package, approved Deck links, and shared Note Type ownership; reject unsafe version or schema mismatches.
- [ ] Treat a Desktop Profile as the owner of one Collection, not a Collection name. Select the Collection separately from entry YAML `deck`; validate approved Deck IDs against that Collection.
- [ ] Require Desktop closed, prevent simultaneous updater runs, honor native lock failures, and release connections on all exit paths.
- [ ] Create and verify a recoverable consistent backup before opening the live Collection: use SQLite's backup API to incorporate committed WAL changes, do not force source checkpoints, and preserve media for recovery. Prepare preview/rehearsal copies without opening the source through Anki; never replace the live Collection with a stale rehearsal copy.
- [ ] Rehearse the complete proposed change on a consistent disposable copy and compare identities, history, content, tags, Card counts, and scheduling before requesting explicit live-apply approval.
- [ ] Revalidate the source inputs and target state before live application; stop if they differ from the approved rehearsal rather than applying stale assumptions.
- [ ] Apply retained Templates/shared styling and YAML Notes/tags, then place only newly generated managed Cards, including those generated by Template changes, in approved existing Decks resolved from YAML `deck`. Preserve every existing Card's Deck ID; do not emit placement-difference warnings.
- [ ] Missing referenced media blocks application. Media uploads/deletion, Deck creation/options, schema migrations, automated Note/Card deletion, and AnkiWeb sync remain excluded.
- [ ] Report committed progress and recovery instructions on interruption or failure; never claim a multi-operation run is atomic or silently restore over newer user work.
- [ ] Integrated tests cover lock contention, duplicate IDs, schema mismatch, missing Deck/media, stale approval, partial failure/recovery, WAL-inclusive snapshots, source immutability during preview, history/scheduling preservation, unchanged existing placement, new-Card placement, and a second-run no-op.
- [ ] Provide a documented opt-in live smoke-test procedure; automated tests and default demonstrations never mutate a real Collection.

## Comments

- 2026-11-16: SQLite backup snapshots remove the need to carry the source WAL alongside the snapshot, not the possibility of WAL files being created later in the disposable or live database. A database snapshot alone is not a complete media backup. Sandbox exploration and this documentation revision do not authorize access to the personal Collection.
