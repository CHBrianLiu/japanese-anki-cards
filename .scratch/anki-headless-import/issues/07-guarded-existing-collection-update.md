# 07: Safely apply the complete workflow to an existing Collection

**What to build:** An author can run the integrated YAML, Note Type, Template, styling, tag, and new-managed-Card placement workflow against an existing Collection through a guarded command. It previews/rehearses on a temporary consistent copy, then permits explicitly approved application only with Anki Desktop closed. Verify the complete workflow against an existing tool-created sandbox Collection, never a personal Collection. No backup, restore, or recovery-package mechanism is built. Existing Card Deck placement is preserved without mismatch reporting.

**Blocked by:** 05 — Apply Note Types, Templates, and shared styling; 06 — Verify new managed Card placement in linked Decks.

**Status:** ready-for-agent

**Verification environment:** Use the dedicated `.venv`, tool-created sandbox Collections with matching manifests, and temporary isolated fixtures documented in [`tools/headless_import/exploration.md`](../../../tools/headless_import/exploration.md). That environment supports end-to-end acceptance, not just preliminary exploration. Historical importer backups, missing-Deck creation, and existing-Card movement are not product requirements.

- [ ] Validate the explicitly selected Collection, compatible Anki package, approved Deck links, and shared Note Type ownership; reject unsafe version or schema mismatches. Exercise selection guards with tool-created sandbox manifests and fixture paths, without inspecting personal Profiles.
- [ ] Treat a Desktop Profile as the owner of one Collection, not a Collection name. Select the Collection separately from entry YAML `deck`; validate approved Deck IDs against that Collection. Any Profile-resolution tests use isolated sandbox fixtures, never the normal Desktop profile registry.
- [ ] Require Desktop closed, prevent simultaneous updater runs, honor native lock failures, and release connections on all exit paths.
- [ ] Prepare temporary consistent preview/rehearsal copies using SQLite's backup API to incorporate committed WAL changes, without source checkpoints or inspection through Anki. The API supplies copy consistency only; do not create/retain recovery backups, archive media, or expose restore. Keep referenced sandbox media available without source writes and dispose of temporary resources. Never replace the target with a rehearsal copy.
- [ ] Rehearse the complete proposed change on a disposable sandbox copy and compare identities, history, content, tags, Card counts, and scheduling before requesting explicit apply approval for the selected sandbox target.
- [ ] Revalidate the source inputs and sandbox target state before application; stop if they differ from the approved rehearsal rather than applying stale assumptions. No backup prerequisite or pre-apply snapshot is added.
- [ ] Apply retained Templates/shared styling and YAML Notes/tags, then place only newly generated managed Cards, including those generated by Template changes, in approved existing Decks resolved from YAML `deck`. Preserve every existing Card's Deck ID; do not emit placement-difference warnings.
- [ ] Missing referenced media blocks application. Media uploads/deletion, Deck creation/options, schema migrations, automated Note/Card deletion, and AnkiWeb sync remain excluded.
- [ ] Report committed progress and fresh-preview/approval requirements for retry on interruption or failure; never claim a multi-operation run is atomic, promise rollback, or restore over user work.
- [ ] Public-command integrated sandbox tests cover lock contention, duplicate IDs, schema mismatch, missing Deck/media, stale approval, partial failure/retry, WAL-inclusive disposable copies, source immutability during preview, history/scheduling preservation, unchanged existing placement, new-Card placement, and a second-run no-op. Verify no backup/media archive/automatic restore artifacts are produced by apply.
- [ ] Provide and execute a documented sandbox-only end-to-end smoke-test procedure using the exploration environment, an explicitly selected tool-created target with a matching manifest, approved links/ownership, closed Desktop, and apply approval. Reopen to verify persisted effects and run again to prove a no-op. Personal/live-Collection smoke testing is not part of this epic or a gate for ticket 08.
